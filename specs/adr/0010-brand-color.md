# ADR-0010 品牌基色采用 #C52935

- 状态：Superseded by [ADR-0012](./0012-brand-color-change.md)
- 决策日期：2026-11-19
- 记录日期：2026-11-19
- 决策者：项目所有者
- 取代：无

## 背景

S1 的 `raw.color.brand.*` 需要一条完整色阶作为锚点，否则 `semantic.color.action.*` 与 `status.*` 无法映射。此前品牌基色一直标记为待输入，阻塞 P3 与 R4 的快照基线。

项目已有视觉识别是红色系。需要决定是沿用现有红、重新定义，还是先用中性色占位。

## 备选方案

**A. 沿用现有红色 #C52935**：不改变既有观感，直接进入色阶生成。

**B. 重新定义品牌色**：重新做品牌决策，S1 等待。

**C. 先用中性灰占位**：链路可先跑通，但 Color 页无法验收红色语义。

## 决策

采用 **A**。品牌基色为 `#C52935`，对应：

```text
oklch(0.539 0.191 22.96)
```

并确定四条细则：

1. 该值作为 `raw.color.brand.500` 的锚点，其余级别按 D4 的「关键级手定 + 公式补全」生成。
2. 源文件 `raw.tokens.json` 只写 oklch；`#C52935` 仅作为决策记录出现在本 ADR 与构建产物的 hex 回退中。
3. 品牌色相固定为 22.96，色阶生成时保持 H 不变，只调整 L 与 C。
4. 品牌级颜色只通过 `brands/<brand>.tokens.json` 覆盖 `raw.color.brand.*`；`semantic` 与 `comp` 的路径不变。

## 理由

1. **延续现有识别**：不引入品牌改版，S1 的验收对象是链路而不是新视觉。
2. **对比度可用**：该色相对白色的对比度为 5.61:1，满足 WCAG AA 正文要求，可直接作为主操作背景配反白文字。
3. **色相稳定**：H 22.96 落在红色区间，色阶生成时固定色相可避免中间级偏橙或偏紫。
4. **转换可逆**：由 sRGB 精确换算得到，不是目测取色，hex 与 oklch 指向同一颜色。

## 后果

- `raw.color.brand.500` 锚定 `oklch(0.539 0.191 22.96)`，`raw.color.brand.50–950` 在 P1 生成。
- 主操作背景配白色文字可用（5.61:1）；配黑色文字仅 3.74:1，不满足正文 AA，禁止在品牌色背景上使用深色正文。
- 暗色模式下 `semantic.color.action.primary.bg` 可能需要指向更浅的级别（如 400 / 300）以保持对比度，具体映射在 P2 的语义映射表中确定，不在本 ADR 预设。
- 状态色（success / warning / danger / info）不随本决策变化，仍按各自色相独立定义。
- 若后续品牌改版，只需替换 `brands/<brand>.tokens.json` 的完整色阶，语义层与组件层不受影响。

## 重新评估的触发条件

1. 品牌视觉升级，#C52935 不再代表品牌。
2. 生成完整色阶后，中间级出现明显偏色或超 sRGB 色域。
3. 暗色模式下无法在现有色阶内找到满足对比度的主操作色。
