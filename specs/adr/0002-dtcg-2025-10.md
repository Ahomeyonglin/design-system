# ADR-0002 以 DTCG 2025.10 作为 token 源格式

- 状态：Accepted
- 决策日期：2026-11-14
- 记录日期：2026-11-15
- 决策者：项目所有者
- 取代：无

## 背景

token 需要同时被 AI、人和第三方工具消费，因此源文件格式决定了整条链路能否被复用。当时讨论过三种载体：纯 CSS 变量、内部 TS/JSON 模型、DTCG 标准 JSON。

同时确认了一个前提：DTCG 2025.10 是社区组（Community Group）的 Final Report，**不是 W3C Standard**，后续会以替代规范的形式更新。

## 备选方案

**A. 纯 CSS**：在 `@theme` 或 `:root` 里直接写变量，无构建步骤。

**B. 内部 TS/JSON 模型**：自定义数据结构，再由脚本导出标准格式。

**C. DTCG 2025.10 三件套**：Format + Color + Resolver，源文件为 `.tokens.json` / `.resolver.json`。

## 决策

采用 **C**，并锁定 2025.10 版本语义；不依赖任何 Editors' Draft。

源文件放在 `packages/tokens/src/`，构建产物输出到 `packages/tokens/dist/`（不入库）。

## 理由

1. **交换格式是现成的**：接 Figma 变量、Style Dictionary、Tokens Studio 等工具不需要重写一遍数据模型。
2. **官方目标是跨平台**：一份文件可生成 Web / iOS / Android / Flutter 代码。源文件因此不能绑定 CSS 概念（例如不该出现 `--var` 命名）。
3. **主题组合有正式机制**：Resolver Module 定义了 sets / modifiers / resolutionOrder，正好覆盖「主题 × 品牌」的需求，不必自造一套。
4. **反面成本高**：先自造 TS 模型再转标准格式，多一层转换，且要自己保证符合规范。

## 由此确定的格式约束

这些是采用 DTCG 后必须遵守的细节，已写入 `specs/tech-stack.md §3`：

- 一个 token = 含 `$value` 的对象；`$type`、`$description`、`$extensions`、`$deprecated` 可选。
- `$type` 只能来自显式声明、引用目标或最近的父 group，**禁止从值反推类型**。
- 名称不得以 `$` 开头，不得包含 `{`、`}`、`.`；`color.brand.600` 是嵌套路径，不是字符串名。
- `$root` 保留，用于表示 group 自身那个 token。
- `dimension` 的 `unit` 只能是 `px` 或 `rem`，值为 0 时单位仍必填。
- `typography` 的 `lineHeight` 是 fontSize 的**倍数**，`letterSpacing` 是 dimension。
- `color` 的 `$value` 不是字符串，必须是 `colorSpace` + `components`；`hex` 只是可选回退。
- 项目自加：`$description` 必填（规范里是可选），作为 AI 判断用途的唯一线索。

## 后果

- 手写 JSON 比写 TS 啰嗦（颜色要写分量数组），这是换取工具兼容性的代价。
- 解析库必须精确锁定版本（不使用 `^`），并配快照测试；格式升级以快照差异为判断依据。
- 生成脚本不能靠「看值猜类型」，必须老实读 `$type` 与 group 继承。

## 重新评估的触发条件

1. DTCG 发布替代 2025.10 的新报告，且不向后兼容。
2. 首批消费方扩展到原生端，需要输出非 CSS 概念的数据。
3. 解析库无法完整支持 Resolver 的 modifier 语义，需要退化为自研组合层。
